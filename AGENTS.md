# AyeOps

Voice-authorized incident command system. Two packages: `backend/` (Python relay) and `web/` (Next.js dashboard).

## Commands

```bash
# Backend
cd backend
uv run test_relay.py                         # offline self-check (prints "ok")
uv run --env-file .env relay.py              # dev server on :8000 (needs ASSEMBLYAI_API_KEY in .env)

# Frontend
cd web
npm ci && npm run build                      # static export → web/out (relay serves this)
npm run lint                                 # ESLint
```

**Required order before PRs:** `uv run test_relay.py` then `npm run build`. CI runs both on push.

## Architecture

- `backend/relay.py` — FastAPI + WebSocket relay. Browser mic → relay → AssemblyAI Voice Agent API. Serves the static dashboard from `web/out`.
- `backend/cluster.py` — SimCluster (in-memory) and DockerCluster (real containers). `INFRA=sim|docker`.
- `web/` — Next.js 16 with static export (`output: "export"`). Dashboard talks to relay over WebSocket on the same origin.
- Authorization code never reaches the model's context. Only the relay verifies it and executes changes.

## Gotchas

- `web/AGENTS.md` is auto-generated by `next dev` — do not delete or edit. `web/CLAUDE.md` just references it.
- `web/out/` is a build artifact (committed). Build the dashboard before starting the relay if you want the UI.
- Autopilot voice clips (`backend/autopilot/clips/`) are not committed. Generate with: `uv run --with gtts python autopilot/gen_clips.py` (needs `ffmpeg`).
- `INFRA=docker` needs `python:3.13-slim` image pulled. A missing image looks like a broken cluster.
- Backend env: `ASSEMBLYAI_API_KEY` (required), `INFRA`, `ALLOWED_ORIGINS`, `MAX_SESSION_S`, `INCIDENT_DIR`.
- The `next dev` agent-rules block in `web/AGENTS.md` is regenerated on every dev run — don't fight it.
