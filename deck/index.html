Why this exists

Instructions are not enforcement.

In July 2025, an AI coding agent deleted a production database during an explicit code freeze it had been told to observe. — The Register, Jul 21 2025 (Replit / SaaStr incident)

Telling an AI what not to do is not a safeguard. The industry has since converged on “AI proposes, a human approves” — but approval today is a click, a chat command, or a policy set in advance. None of it proves which human approved this exact change, independent of the AI's own output.

The failure 02 / 11

The principle we introduce and define

Blind Clearance

An AI must never hold the means to authorize its own action.

  1. 01

    The secret never enters the model's context

    The authorization code is generated by the relay and shown only on the operator's screen. The model is never told it, so it cannot say it, guess it, or hallucinate having heard it.

  2. 02

    A human reads the change back, with the secret

    Not “yes.” The operator says the action, the service, and the code together — proof they understood what they're approving, not just that they can read two words off a screen.

  3. 03

    A separate authority executes — never the model

    The relay verifies the readback and runs exactly the authorized change. The model is outside the trigger path entirely, even if it were fully compromised.

Blind Clearance 03 / 11

One incident, start to finish

What the judge watches happen

  1. 1

    The page

    A bad deploy ships. Auth crash-loops for real. AyeOps speaks first — it pages the operator before being asked.

  2. 2

    Autonomous triage

    Read-only health and log checks, root cause stated in one sentence. No human needed yet.

  3. 3

    The proposal

    AyeOps proposes exactly one fix. Nothing has changed. It cannot execute — only propose.

  4. 4

    The clearance slip

    A one-time code appears on the operator's screen only. The model is never shown it.

  1. 5

    The readback

    “Roll back auth-service, Lima Charlie.” The relay checks the action, the service, and the code — then executes.

  2. 6

    Narrated recovery

    Rollout progress spoken live. Red → green in well under a minute.

  3. 7

    The postmortem

    Filed automatically, with the verbatim voice authorization and AssemblyAI's own recording as evidence.

  4. 8

    Resilience

    The voice link is cut mid-incident, on purpose. Recovery in under two seconds — the pending authorization survives.

Differentiation 07 / 11

Application of technology

We mapped the API's edges, not just its surface

Six surfaces, each for a measured reason

Single-connection STT+LLM+TTS over browser PCM16 · hold-mode tools everywhere · reply.create for proactive paging and narration · mid-session session.update for phase-scoped tools and verified recall · the Sessions REST API for audit evidence · keyterms tuned for reliable code transcription.

Three places we proved the docs wrong

Interactive filler clocked a 93ms tool at 5.9s, in AssemblyAI's own session timeline. Hold-mode tool results must always be delivered after a barge-in, or the agent freezes for 60s. session.resume was refused across 11 variants — so the relay stopped depending on it and rebuilds context from its own record instead.
